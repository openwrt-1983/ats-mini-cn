The second sleep mode is now "CPU off" instead of "unlocked". It stops the CPU (`esp_light_sleep`), switches Wi-Fi and Bluetooth off and keeps the receiver playing, which is what the mode is for: with the display dark there is nothing left but the radio.

The implementation is a light sleep on purpose. A deep sleep version was tried first and kept falling silent on real hardware, because with the digital domain powered down the four rails the receiver depends on -- the LDO enable (`PIN_POWER_ON`), the SI4732 reset (`RESET_PIN`), the amplifier enable (`PIN_AMP_EN`) and the hardware mute (`AUDIO_MUTE`) -- survive only if the RTC IO mux and the hold function both take, and there is no way to tell from the outside which one gave way. Light sleep keeps the digital domain powered, so those pads simply keep the levels they already had; there is no transition to survive, and the audio cannot be lost.

Waking is armed on the encoder button and both encoder phases through the light sleep GPIO wake-up (any low): a click and a single detent both bring the unit back. The wake is in place -- no reset, no splash screen, no gap in the audio -- and the detent that woke the unit is swallowed instead of being applied as a tuning step. Wi-Fi and Bluetooth are restarted on the way out, and the sleep timer's reference point is refreshed so the unit does not blank itself again on the first pass of the main loop.

Because the firmware stops running, the mode also watches the off timer itself: a pending shut down is armed as a sleep timer, so an unattended power off still happens instead of waiting for somebody to touch the knob. Wakes that are not caused by the knob no longer light the display; they are retried, paced by a timer once they repeat, so a wake storm cannot turn the mode into a busy loop.

Also fixed: a queued Wi-Fi/Bluetooth restore from the off timer no longer switches the links back on while the unit is asleep, and the standby wake release wait in `setup()` is bounded, so a pad that never comes up cannot hold the boot.
